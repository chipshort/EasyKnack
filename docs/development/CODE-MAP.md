# EasyKnack code map

Developer navigation index. Start with the task row, then inspect only the relevant
files and their callers/tests. This is a locator, not an API contract or a complete
file inventory; verify behavior in current code. Update affected rows when moving
files, adding a subsystem or changing ownership. Do not add debugging transcripts.

## Ownership and flow

EasyKnack owns audio policy, DSP, units, node definitions, application menus and
its document migrations. GLSwing owns generic widgets, graph editing, composites,
history, document mechanisms and rendering. EasyKnack consumes an external Maven
artifact; a Core checkout is never a source/build dependency of the application.
See [ownership details](CORE-BOUNDARY.md).

Typical execution path: WorkspaceController -> GroupCompiler / special-group
preparation -> Core graph flattening -> AudioGraphEncoder -> AudioHostService /
AudioHostClient -> native host. Bake/export has its own source-generation path.

## Core navigation

In a separate GLSwingNext checkout, start with `docs/CODE-MAP.md`.
For group boundary wiring specifically: GLNodeWorkspace -> composite interface
transactions/descriptors -> GLCompositeGraphFlattener / GLCompositeForwarding.
For sliders, picking, tabs or labels: start in Core ui/, not AudioNodeFactory.

- Language and preferences: `i18n/AppText`, `app/ApplicationSettings`; old public `ui` names delegate for compatibility. Preferences retain their original node.
- Compilation kernels: `compiler/MathFusion`, `SampleFusion`, `StatefulChainSpecialization`, `SpectralSourceSpecialization`, `CompiledManualTargets`. `ui/GroupSourceExporter` orchestrates application group metadata.
- View-independent execution policy: `graph/GraphExecutionPolicy`; `WorkspaceController` delegates composite and leaf Mute/feedback preparation. Neutral Digital Noise stays executable with a native bypass flag (Factor 1, Frequency forwarded, Trigger silent); instance/spectral leaf preparation shares this policy. `ControlOutputsTest` covers routing and MIDI voice/pitch behavior.
- Native build policy: `native/audio-host/build.properties`, `scripts/NativeBuild.ps1`, plugin `NativeBuildSettings`; host scripts and packaging share one invocation. CMake reads the same policy and requires Maven-generated contracts.
- Native root headers forward to implementation folders, preserving exported SDK include paths. Deferred driver sources: `native/experimental/virtual-audio`.
- Cleanup progress, validation and deliberately retained material: [CLEANUP-PLAN.md](CLEANUP-PLAN.md).
